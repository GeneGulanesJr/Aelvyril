Design choices baked in: ① memory.db lives on a shared volume in WAL mode — gateway children (LaPis extension) read/write it directly; the lapis container is the HTTP/MCP API surface over the same file. ② Each conversation = its own pi --mode rpc child process (own cwd + env, crash isolation); all agents in a conversation share one LaPis namespace via LAPIS_PROJECT_KEY. ③ workspaces/ is a host bind mount shared by gateway (rw) and sandd (per-profile mounts) — sandbox escape stays promote-only.
